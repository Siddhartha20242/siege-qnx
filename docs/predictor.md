# Interference predictor

A neural network written from scratch (numpy for training, plain C for inference on the target; no framework) that reads the first seconds of a run's latency samples and predicts whether the run will fail and which pattern it is. Two hidden layers of 32 units, 1829 weights per network. Trained on 1380 runs (257 failing) from the full matrix, QEMU emulation. It sees only per-second late and lost counts and latency percentiles; it is not told the attacker or the profile.

## Does it warn early, and better than a plain rule?

Failure prediction, tested leave-one-attacker-out: each score is on an attack type the network was not trained on. The rule alarms on any silent second, more than 2% late or lost frames, or a p99 over the deadline.

| Seconds of evidence | Network F1 | Network recall | Network precision | Rule F1 | Rule recall | Rule precision |
|---|---|---|---|---|---|---|
| 1 | 0.40 | 0.41 | 0.40 | 0.52 | 0.40 | 0.73 |
| 2 | 0.86 | 0.84 | 0.89 | 0.89 | 0.98 | 0.82 |
| 3 | 0.95 | 0.95 | 0.96 | 0.88 | 0.98 | 0.79 |

## Verdict

* The network beats the rule on unseen attackers with 3 s of evidence (F1 margin over 0.02).
* The rule is better with 1, 2 s.
* The plain rule already reaches F1 0.85 with 2 s of evidence, so the network does not warn earlier than a rule that costs nothing to write; what it adds, where it wins, is fewer false alarms.

## Limits

* Trained and tested on emulator data from one image and one deadline (20 ms). On hardware the timings, and so the features, would differ and it would need retraining.
* Leave-one-attacker-out is a hard test, but the attacks come from one author and share structure (several are CPU hogs in different clothes).
* The network cannot know why a run is failing, only that its latency looks like runs that failed. It is an early-warning signal, not a diagnosis.
* The numbers here come from the results files in `docs/results/full-*.json` and are regenerated by `tools/train_monitor.py`.
